# Thêm nút "Điều hướng" per-account (chat / image / video) và lọc account theo loại request

## Context

Hiện tại mọi account trong pool đều nhận mọi loại request. Khi một account không phù hợp với request (ví dụ bị gửi video), request đó sẽ lỗi. Cần cho phép mỗi account tự đánh dấu các loại request được phép xử lý (**chat / image / video**, mặc định bật cả 3), và gateway phải phân loại request (loại đã có sẵn theo từng endpoint) để chỉ điều hướng đến account đã bật loại đó.

Loại request đã được xác định sẵn theo endpoint: `ModelKind = Literal["chat", "image", "video"]` (`src/muse2api/core/models.py:10`), gateway biết loại qua `chat_stream` / `generate_image` (hint `media:image`) / `generate_video` (hint `media:video`) — `src/muse2api/services/gateway.py:55,103,113`.

## 1. Model — `src/muse2api/accounts/model.py`

- Thêm model `Routing(BaseModel)`: `chat: bool = True`, `image: bool = True`, `video: bool = True`.
- `Account` thêm trường `routing: Routing = Field(default_factory=Routing)`.
- Thêm helper `Account.allows(kind: str) -> bool` (`getattr(self.routing, kind, True)`).
- `public()` tự động trả về `routing` qua `model_dump` → dashboard hiển thị được ngay, `data/accounts.json` tự round-trip (persist qua `JsonAccountStore` không cần sửa).

## 2. Pool — `src/muse2api/accounts/pool.py`

- `_candidates(exclude, kind=None)` (`:144`): bỏ qua account có `kind` bị tắt (`not acc.allows(kind)`); `busy`/`back_at` chỉ tính trên account đủ điều kiện kind (tránh chờ nhầm account không bao giờ nhận loại đó).
- `has_alternative(exclude, kind=None)` (`:162`): thêm điều kiện `a.allows(kind)` — để failover không retry khi không còn account phù hợp.
- `acquire(..., kind=None)` (`:168`) và `lease(..., kind=None)` (`:250`): thread `kind` xuống; đầu hàm, nếu `kind` được truyền mà không còn account nào (ngoài `exclude`) đủ điều kiện → raise `NoAccountAvailable(f"no account is enabled for '{kind}' requests")` ngay lập tức (HTTP 503, code `no_account_available` — `src/muse2api/errors.py:51`) thay vì chờ `acquire_timeout`.
- Đường path pin `X-Account-ID` (`acquire` với `account_id`) **giữ nguyên hành vi bypass** như hiện trạng (đã bypass `enabled`/`status`) — pin là lựa chọn tường minh của người gọi.

## 3. Gateway — `src/muse2api/services/gateway.py`

- `_lease` (`:28`) thêm `kind=None`, truyền vào `pool.lease`; `_run` (`:79`) thêm `kind=None` truyền xuống `_lease`; `_should_retry` (`:40`) truyền `kind` vào `has_alternative`.
- Gọi với kind tương ứng: `chat_stream` → `"chat"`, `generate_image` → `"image"`, `generate_video` → `"video"`. Các hàm quản lý thread (`list_threads`, `thread_messages`, rename/delete) không truyền kind — luôn dùng được với mọi account.

## 4. Admin API — `src/muse2api/api/schemas.py` + `src/muse2api/api/routes/admin.py`

- `AccountUpdate` thêm `routing: Routing | None = None` (import `Routing` từ `accounts.model` — không gây circular import).
- `update_account` (`admin.py:123`): `if body.routing is not None: acc.routing = body.routing` (thay cả 3 flag; dashboard luôn gửi đủ 3), rồi `pool.upsert` như hiện tại.

## 5. Dashboard — `src/muse2api/web/dashboard.html`

- `accountCard()` (`:1734`): thêm nút `<button data-act="routing">Điều hướng</button>` vào `.acc-actions` (ngay sau nút "Sửa"), kèm tooltip; thêm 1 dòng nhỏ hiển thị trạng thái (chỉ khi có loại bị tắt, ví dụ "Video: tắt") để nhận biết nhanh.
- Click dispatcher (`:1884`): thêm nhánh `if (act === "routing" && a) return guarded(() => routingModal(a));`.
- Hàm mới `routingModal(a)` theo đúng pattern `editAccount` (`:1851`): dùng `modal()` có sẵn, body gồm 3 checkbox `label.chk` xếp dọc — **Chat / Tạo ảnh (image) / Tạo video**, mặc định checked theo `a.routing || {chat:true,image:true,video:true}`; action "Lưu" với:
  - `check()`: bắt lỗi nếu không chọn loại nào ("Phải chọn ít nhất một loại request").
  - `collect()`: `{routing: {chat, image, video}}`; `submit()`: `PATCH /admin/accounts/{id}`.
  - Sau lưu: `toast("Đã cập nhật điều hướng")` + `loadAccountsPage()`.
- Auto-refresh đã tự skip khi modal mở (`state.modalOpen`) — không cần sửa.

## 6. Docs — `docs/API_REFERENCE.md`

- Cập nhật dòng PATCH `/admin/accounts/{id}` (bảng `:450`): mô tả thêm trường body `routing {chat, image, video}`.

## 7. Tests — `tests/test_pool.py` (theo pattern có sẵn: tạo `AccountPool` với store tmp_path)

- Account có `routing.video=False` không bao giờ được lease cho `kind="video"` nhưng vẫn được lease cho `kind="chat"`.
- Khi không còn account nào bật kind đó → `acquire` raise `NoAccountAvailable` ngay (không chờ timeout).
- `has_alternative(exclude, kind)` có tính kind.
- Gateway failover: account đầu bị tắt kind → tự chuyển sang account khác; chỉ có 1 account bị tắt kind → lỗi gốc lan lên.
- (Nếu `test_api.py` đã có test PATCH account → thêm 1 case PATCH `routing` và kiểm tra response/persist.)
